# 非秘密 .env による Setup と同じ端末の更新

Goコアの`--env-file`は、本人が許可範囲やTunnel IDを変更するときの入力補助です。通常の版更新にはSetupやキー再入力を使わず、正式Releaseの新exeから`update`を実行します。[導入・更新の入口](quickstart.md)を参照してください。正式配布は[Release v0.2.8](https://github.com/Xpotato1024/xpotato-mcp-tunnel/releases/tag/v0.2.8)です。

## 推奨形式

`setup.env.example` を `setup.env` にコピーし、UTF-8 のテキストで編集します。端末名・Tunnel ID・許可フォルダーだけを入れます。API キーはこのファイルへ書かないでください。

```dotenv
DEVICE='work-pc'
TUNNEL_ID='tunnel_YOUR_ID'
ALLOW_DIR_1='D:\Apps With Spaces'
ALLOW_DIR_2='C:\Work'
```

これはリテラルな設定データです。外側の単引用符は取り除き、Windows のバックスラッシュ・空白・`#`・`$` はそのまま保持します。変数展開、エスケープ処理、shell 実行、環境変数への設定はしません。引用符なしでも指定できます。二重引用符、`export`、行末コメントは使いません。コメントは独立した行の先頭を `#` にしてください。

許可する名前は `DEVICE`、`TUNNEL_ID`、`ALLOW_DIR_1` から `ALLOW_DIR_100` だけです。`DEVICE`、`TUNNEL_ID`、少なくとも `ALLOW_DIR_1` が必須で、フォルダー番号は 1 から連続させます。端末名は英小文字・数字・ハイフンで 1〜64 文字、先頭は英小文字か数字。Tunnel ID は `tunnel_` で始まる有効な識別子です。フォルダーは実在する絶対パスで、重複を拒否します。UTF-8 BOM、LF、CRLF を受け付け、ファイル上限は 64 KiB です。未知の名前、重複、欠番、不正値は行番号またはフォルダー番号付きで拒否し、拒否した値は表示しません。

API キーの設定名を追加しても読み込み・保存できません。Git は `setup.env` と `.env` 系を除外しますが、秘密は最初から書かないでください。実 Tunnel ID をソースの fixture や example に入れません。

## 本人の操作手順

1. レビュー・採用済みの実行ファイルとチェックサムを確認します。本人の通常ユーザーの対話端末で操作します。Windows は Credential Manager、Linux は解除済みのユーザー Secret Service が必要です。
2. `setup.env` の値を編集します。既存端末を更新するときは、保存済みと同じ端末名・恒久保存先を指定します。
3. Windows は `.\xpotato-tunnel.exe setup --env-file .\setup.env`、Linux は `./xpotato-tunnel setup --env-file ./setup.env` を実行します。既定以外の保存先なら `--home` に同じ絶対パスを毎回指定します。任意で `--command-dir`、検証済み直接接続先の `--mcp-url` も使えます。`--device`、`--tunnel-id`、`--allow` と `--env-file` は併用できません。
4. 保存前の確認画面で端末名、Tunnel ID、許可フォルダー、恒久保存先、Go 本体・runtime・profile・ラッパー・短縮コマンドの場所を確認します。既存設定では変更前の実際の範囲と変更後の範囲を表示します。手動で絞り込んだ既存 profile でも、`.env` の一覧に広がる場合は差分として表示します。`.env` は実際の範囲をこの一覧へ切り替える指定です。
5. `yes` で確定します。確定までは保存、runtime 導入、Vault 操作、接続起動はしません。`no` / `q` で中断し、`device` / `tunnel` / `dirs` / `home` / `command` で修正できます。`.env` 自体は書き換えません。対話で修正した内容を次回も使う場合は本人がファイルへ反映します。
6. 新規端末または Tunnel ID 変更時は、OS 資格情報ストアへの保存に別途 `yes` で同意し、API キーだけを非表示で入力します。同じ Tunnel ID の完了済みキーは読み取りも再入力もせず保持します。Tunnel ID を変更して戻しても以前のレコードを上書きせず、新しいレコードを作ります。任意の短縮コマンドの配置は別途同意し、PATH は変更しません。
7. Setup 完了後、本人が接続するタイミングで、表示された `start` コマンドを実行します。短縮コマンドが既存 PATH にあれば引数なしの `xpotato-tunnel` で起動できます。Setup 自体は起動・停止を行いません。同じ ID の既存プラグインを再利用し、アカウント登録は本人が必要時だけ UI で行います。

追加の永続環境変数は不要です。ファイルは明示した `--env-file` だけを読み、自動探索しません。ファイルなしの `setup` は従来の対話入力を使います。Linux では Linux 側の絶対パスを使い、Windows のドライブ表記をそのまま渡しません。

## 保存後の変更と失敗時

`setup.env` を編集し、同じコマンドを再実行します。別の端末名を作る必要はありません。追加・拡張・縮小・Tunnel ID の差分を確認し、再度明示的な `yes` が必要です。起動中の端末または変更前後の Tunnel が使用中なら拒否します。自動停止や再起動はしません。設定作成が未完了の端末は、まず保存済みと同じ値で Setup を完了してから変更します。

範囲変更では旧 profile を保持して別 profile を準備し、他の Commander 設定を保持します。確認後に旧 device/config が変われば拒否します。新 profile の準備・runtime 検証・キー保存・本体導入が成功してから device.json の参照を一度に切り替えます。Start は起動ロック取得後に最新設定を読み直します。

公開前の失敗では旧端末の参照を保持します。未参照 profile/runtime や新しい専用キーのレコードが残る場合があります。新キー保存後・参照公開前に失敗した Tunnel 変更の再試行では、新レコードへの同意とキー入力を再度求める場合があります。以前のレコードは削除しません。参照公開後に登録案内・既定端末の保存が失敗した場合は「更新は保存済み」と表示し、同じ Setup で後段を再開します。通常の新規 Setup の途中再開では完了済みキー保存を繰り返しません。

許可フォルダーは Desktop Commander のファイルツールのパス確認です。プロセス実行全体を閉じ込める sandbox ではありません。広いルートの配下には認証ファイル等も含まれ得るため、本人が一覧を確認して必要な範囲を採用します。Windows の WSL 物理ディスクを許可しても、Linux 内部パスや別の UNC 名前空間を検証・許可したことにはなりません。
